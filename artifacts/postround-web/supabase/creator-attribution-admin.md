# Admin Creator Attribution read contract

The admin pages read `creator_profiles` (including inactive/no-link identities), `creator_referral_links`, `creator_referral_events`, `creator_attributions` and narrowly scoped `profiles` subscription fields. They require a verified admin session and server-side service access; there is no public data endpoint or export. The web server must have a service role key for this read-only view. A bounded admin capability check runs before data reads so a mistakenly configured anon key cannot make RLS-hidden records appear to be valid zeroes.

Overview creator/link/event/attribution counts use Supabase `count: exact, head: true`, not the returned row array length. An event is one recorded click, including unclaimed clicks; it is **not** a player or install. One immutable attribution row belongs to one authenticated player. An attributed subscriber is an attribution whose joined player profile **currently** has `subscription_status = active`. It is not a historical subscription conversion, verified purchase, payable revenue, or commission. The current schema does not define qualifying subscriptions, a rate, payout status/period, revenue, or payouts; compensation is **Not configured**.

Creator metrics are all-time. The detail event list filters on `occurred_at` and the attribution list on `attributed_at`; selected dates are UTC days with an inclusive end date. Platform on events is click platform; attribution method/source are separate claim evidence. Status filters use the player's current profile subscription status. Pagination is server-side at 20 rows per list; counts are exact across all pages. Original creator identity is `creator_profiles.id`, not the optional owner account or a favorite creator.

A checked-in migration is **not** proof of installation in the connected environment. Missing tables/columns, missing service access and query failures render unavailable notices rather than valid zeroes. The service role key and referral migration still require separate deployment verification. The pages never modify referral records.
