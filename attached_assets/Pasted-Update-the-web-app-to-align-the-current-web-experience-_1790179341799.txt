Update the web app to align the current web experience around the **Creator Dashboard** and **Creator Studio**. This is a navigation, terminology, presentation, and small workflow enhancement only. Do NOT redesign or refactor the existing Creator Studio content or backend architecture.

## Product direction

The current web landing page is the **Creator Dashboard**. It is the creator's home/landing page.

The existing creator content/workflow page should now be called **Creator Studio**.

Use this terminology consistently throughout the web UI:

* **Creator Dashboard** = landing page/home for the creator
* **Creator Studio** = creator content/workflow workspace

Do not introduce or expose a player-facing web dashboard at this time. Player web functionality is future scope.

## 5. Creator Studio — Refresh Available Content

Add a button directly **below the existing Creator Studio header**:

**Refresh Available Content**

### Location

The button must appear immediately below the existing Creator Studio header and **before the existing story/content cards or available-content list**.

Do not place it in the global navigation, inside an individual story card, or at the bottom of the page.

The existing Creator Studio header itself should remain unchanged.

### Functionality

The button must actually refresh the available creator content.

When the creator clicks **Refresh Available Content**:

1. Re-fetch the current available creator content/stories from the server.
2. Use the **existing Creator Studio API/contract and existing data-fetching mechanism** wherever possible.
3. Update the Creator Studio content/list in place without requiring a full browser/page reload.
4. Newly available stories/content should appear after the refresh if they are now available to that creator.
5. Show a clear loading state while the refresh is running.
6. Prevent duplicate/concurrent refresh requests while a refresh is already in progress.
7. Handle API/network errors gracefully and provide an appropriate error state/message.
8. Preserve the creator's current page state where practical.

### Critical architecture constraint

**Refresh Available Content must only re-fetch/discover currently available content.**

It must NOT:

* generate a new story
* run story qualification
* create a new story candidate
* regenerate creator content
* trigger the creator story engine
* trigger the player story engine
* trigger Coaching Reflection generation
* alter approval status
* modify permissions
* create duplicate content

The refresh operation should simply ask the existing backend/data source for the **current state of available creator content**.

### API guidance

Before creating anything new, inspect how the Creator Studio currently loads its available stories/content.

**Reuse the existing API endpoint, service, hook, query, or contract for the refresh operation if possible.**

Only introduce a new endpoint or backend functionality if the existing architecture genuinely cannot support re-fetching the current available content.

Do not modify the existing creator API contract unnecessarily.
