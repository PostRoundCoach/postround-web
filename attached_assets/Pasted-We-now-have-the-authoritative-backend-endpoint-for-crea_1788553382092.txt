We now have the authoritative backend endpoint for creator-generated content:

`GET /api/content/ideas?story_id=<uuid>`

This task is ONLY for the existing Next.js Creator Story Dashboard frontend.

## Context

The Creator Story Dashboard already has:

* authenticated Supabase user/session
* creator identity/profile lookup
* permissioned creator story queue
* story cards
* existing Generate Content action
* existing client integration with the authoritative Post Round API
* `NEXT_PUBLIC_POSTROUND_API_BASE_URL`

The authoritative backend now provides:

### Generate

`POST /api/content/generate`

Request:

```json
{
  "creator_id": "<creator-profile-id>",
  "story_id": "<story-id>"
}
```

Authenticated using:

```http
Authorization: Bearer <Supabase access token>
```

Successful response:

```json
{
  "ok": true,
  "count": 3
}
```

### Retrieve generated ideas

`GET /api/content/ideas?story_id=<story-id>`

Authenticated using the same:

```http
Authorization: Bearer <Supabase access token>
```

Successful response:

```json
{
  "ok": true,
  "ideas": [
    {
      "id": "uuid",
      "story_id": "uuid",
      "category": "Round Analysis",
      "title": "Example title",
      "hook": "Example hook",
      "script": "Example script",
      "created_at": "ISO timestamp"
    }
  ]
}
```

An authorized story with no generated ideas returns:

```json
{
  "ok": true,
  "ideas": []
}
```

The backend is the source of truth for authorization. The web app must NOT attempt to recreate creator/story authorization logic.

```text
Generate Content

{ ok: true, count: 3 }
       ↓
GET /api/content/ideas?story_id=<story-id>

Render generated ideas
```

# 6. Loading states

Handle these states explicitly:

### Generating

Show the existing generation loading state and disable the generation action.

### Fetching generated ideas

After successful generation, show a brief loading state while retrieving the persisted ideas.

Do not leave the user staring at a successful “3 ideas generated” message with no content.

### Loaded

Render the actual ideas.

### Empty

If generation returns:

```json
{
  "ok": true,
  "count": 0
}
```

or the subsequent GET returns:

```json
{
  "ok": true,
  "ideas": []
}
```

show a useful non-error state explaining that no generated ideas are currently available.

Do not fabricate content.

### Error retrieving ideas

If generation succeeds but the GET request fails:

* preserve the story card
* tell the creator that generation completed but the generated ideas could not be loaded
* provide a Retry action for retrieving the ideas
* do not automatically generate again

This distinction is important: **Retry retrieval must not call POST /generate again.**

---

# 7. Retry behavior

There are two different failure cases:

### Generation failure

Retry should call:

`POST /api/content/generate`

again.

### Retrieval failure

Retry should call only:

`GET /api/content/ideas?story_id=<story-id>`

Do not regenerate content unnecessarily.

---

# 8. Avoid duplicate generation

Do not automatically call `POST /api/content/generate` when the page loads.

Do not regenerate when:

* the dashboard rerenders
* a story card expands
* generated ideas are copied
* generated ideas are fetched
* the creator navigates back to the dashboard

Generation remains an explicit creator action.

---

Do not add any service-role Supabase access.

Do not query `content_ideas` directly from the browser.

The browser should retrieve generated ideas only through:

`GET /api/content/ideas?story_id=<story-id>`

# Definition of done

The creator experience works end-to-end:

1. Creator opens an authorized follower story.
2. Creator clicks **Generate Content**.
3. Web calls `POST /api/content/generate`.
4. API confirms generation with `{ ok: true, count }`.
5. Web calls `GET /api/content/ideas?story_id=...`.
6. API returns the creator-authorized generated ideas.
7. Dashboard renders the real title/hook/script.
8. Creator can copy the hook or script.
9. Retrieval errors can be retried without regenerating.
10. Unauthorized stories remain inaccessible because authorization stays entirely in the authoritative API.
11. Existing tests, TypeScript, and production build pass.
