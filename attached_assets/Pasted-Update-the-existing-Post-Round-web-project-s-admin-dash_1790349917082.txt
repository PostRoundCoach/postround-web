Update the existing Post Round web project's **admin dashboard** at `/admin`.

## Objective

Add a new admin dashboard tile called:

# Creator Attribution

This tile will become the central admin area for monitoring the creator referral/attribution system and, eventually, calculating and tracking creator compensation.

The referral infrastructure is **already implemented** in the database. Do not create a new referral system.

The existing backend includes:

* `referral_links`
* `referral_events`
* `attributions`
* existing referral creation/issue RPC
* existing referral claim RPC
* creator relationships
* user/subscription information

Use the existing infrastructure and database relationships.

# 3. Creator attribution hierarchy

The conceptual funnel should be:

Creator

→ Referral Link

→ Referral Event

→ Attribution

→ User

→ Subscription

→ Compensation

The UI should preserve these distinctions.

In particular:

**Referral events are NOT the same thing as attributed users.**

An event indicates referral activity.

An attribution indicates that a user has actually been associated with the creator.

A subscription indicates monetization after attribution.

Compensation should only be shown/calculated when the existing business rules and database information support it.

---

Clicking a creator in the table should open a detailed view.

Show:

* Creator slug
* Creator ID

* Active/inactive state if available

### Referral activity

* Total referral events
* First event

### Attributed players

Show the users attributed to that creator.

Suggested columns:

| User | Attributed | Source | Subscription | Tier |
| ---- | ---------- | ------ | ------------ | ---- |

Use the existing user/subscription data.

### Compensation

Show compensation information where supported by the existing system.

At minimum, design the UI so that compensation can eventually include:

* Attributed subscribers
* Qualifying subscriptions
* Gross revenue
* Creator share/rate
* Calculated creator compensation
* Compensation status
* Compensation period

**Do not invent compensation rules.**

If the application does not yet have an authoritative compensation calculation, display the appropriate data that exists and leave the compensation calculation clearly marked as not yet configured rather than making up a formula.

# 8. Compensation architecture

This page is intended to eventually become the authoritative admin interface for creator compensation.

However, **do not invent or hard-code a compensation model in this task**.

Instead:

1. Inspect whether the existing project already contains compensation/revenue-share logic.
2. Reuse it if it exists.
3. If it does not exist, structure the UI so compensation can be added cleanly later.
4. Clearly distinguish actual calculated compensation from placeholder/unconfigured compensation.

Do not silently assume a percentage or payout rule.
