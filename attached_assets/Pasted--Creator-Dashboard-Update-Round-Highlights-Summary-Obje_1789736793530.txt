## Objective

The **Round Web Contract has already been updated from the app**, and scoring integrity has been confirmed on the application side.

The current embedded round data is correct and must remain embedded.

**Do not redesign or modify the underlying Round Web Contract. Do not recalculate round statistics from hole-level data.**

This task is narrowly focused on updating the **default Round Highlights / embedded round summary presentation** in the Creator Dashboard so it is more useful to a creator scanning a generated story.

The complete hole-by-hole round data must remain available through the existing expandable:

**View full round details →**

# 3. Compact Scoring Summary

This is the primary change.

Use the existing authoritative round-level scoring statistics from the Round Web Contract / `rounds` record.

**Do not recalculate scoring categories from hole-level data in the web client.**

Available scoring fields include:

* `hole_in_one`
* `albatrosses`
* `eagles`
* `birdies`
* `pars`
* `bogeys`
* `double_bogeys`
* `triple_bogeys`

Display **only non-zero categories**.

Prioritize exceptional scoring categories before ordinary scoring categories.

Suggested display order:

1. Hole-in-one
2. Albatross
3. Eagle
4. Birdie
5. Par
6. Bogey
7. Double bogey
8. Triple bogey

Examples:

If the round contains:

* 1 hole-in-one
* 1 eagle
* 4 birdies
* 8 pars
* 3 bogeys

display:

**1 Hole-in-one · 1 Eagle · 4 Birdies · 8 Pars · 3 Bogeys**

If the round contains:

* 2 birdies
* 3 pars
* 2 bogeys
* 1 double bogey
* 1 triple bogey

display:

**2 Birdies · 3 Pars · 2 Bogeys · 1 Double Bogey · 1 Triple Bogey**

If there are no exceptional scores, simply omit them.

Do not invent a `double_plus` field.

Do not collapse all 2+ over-par scores into `Double+` if the contract provides the actual `double_bogeys` and `triple_bogeys` counts.

The goal is to surface meaningful scoring events to a creator.

A hole-in-one, albatross, or eagle is potentially much more important to a creator than simply treating it as a generic “under par” event.
