## Complete the Creator Studio API Fix — Verify, Implement, Test, and Report

The previous investigation (Task #154) identified a likely API route mismatch, but marked the task complete without validation. No code changes or deployments were made.

**This task is not complete until the actual implementation has been verified and the acceptance criteria below are satisfied.**

### Context

The Vercel Preview website uses:

`NEXT_PUBLIC_POSTROUND_API_BASE_URL=https://api.postroundcoach.com`

The website expects these authenticated API endpoints:

- `GET /api/content/stories`
- `GET /api/content/creator-summary`
- `GET /api/content/ideas`

The previous investigation found that the workspace API contains the stories and creator-summary handlers, while the separate `PostRoundCoach/postroundcoach` repository at commit `26389f9f447f084b2aa43b9bdf4f35817593c269` did not contain these two GET handlers.

The exact deployed commit serving `api.postroundcoach.com` was not established. Unauthenticated requests returned generic 401 responses, which did not prove whether the routes existed.

2. Verify this through available deployment/domain configuration or deployment logs. Do not infer deployment identity solely from HTTP responses.
3. Record the current deployed commit or source version if available.
4. Identify the intended production Supabase project without displaying credentials or secret values.

**Do not proceed by editing a repository unless you have established that it is the repository serving the custom API domain.** If this cannot be established, stop and report exactly what evidence is missing.

### Phase 2 — Inspect and implement the smallest safe fix

In the confirmed target API, inspect the existing content router, authentication middleware, data-access functions, and relevant workspace handlers.

If the two handlers are missing, port or adapt their complete existing implementations:

- `router.get("/stories", ...)`
- `router.get("/creator-summary", ...)`

The existing mounts already provide `/api/content`. Do not add another `/api` prefix or change the website's API base URL.

Requirements:

1. Preserve existing authentication and the established error/response formats.
2. Enforce creator ownership and authorization server-side.
3. Preserve story permission and revocation checks. Do not expose stories without valid permission.
4. Ensure the stories endpoint returns the fields and data shape the website expects.
5. Ensure creator-summary returns all required fields, including the correct follower count.
6. Reuse appropriate existing data-access logic rather than introducing a parallel implementation or hardcoded data.
7. Keep `GET /api/content/ideas` and all existing mobile API endpoints working as before.
8. Do not change Supabase URLs, credentials, secrets, database contents, or unrelated routes.
9. Do not replace the entire API or make broad authentication/router changes.

If an existing handler cannot be safely ported because of incompatible schema, auth, or response contracts, stop and explain the blocker instead of guessing.
