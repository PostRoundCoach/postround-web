We need to troubleshoot two related Creator/Story workflow issues in production. **Do not make speculative changes. Trace the existing implementation and identify the root causes first, then make the smallest correct fixes.**

## Current observed behavior

I have tested logging in/out of the Creator Dashboard.

### Issue 1 — Story state is not persisting across logout/login

While logged in as a creator:

* Stories load correctly.
* If I click **Dismiss**, the story disappears as expected.
* If I click **Request Approval**, the button immediately changes to **Approval Requested** as expected.

However, after logging out and then logging back in:

* Previously dismissed stories reappear.
* Stories that previously showed **Approval Requested** revert to **Request Approval**.

This strongly suggests that the dashboard's displayed story state is either:

* not being persisted to the correct database record,
* being persisted but not queried when the dashboard reloads,
* being persisted to the wrong user/story relationship,
* or being derived from transient frontend state instead of durable database state.

### Issue 2 — Approval request is not appearing for the follower in the app

When the creator clicks **Request Approval**, the creator sees **Approval Requested**, but the affected follower/user does not receive/see the approval request anywhere in the Post Round app.

We need to trace the entire approval-request lifecycle:

Creator → approval request creation → database → follower → app query → UI.
