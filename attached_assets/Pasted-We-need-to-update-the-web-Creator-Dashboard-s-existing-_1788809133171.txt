We need to update the web Creator Dashboard's existing **"Generate Content"** button.

## Context

The creator dashboard is now successfully receiving and displaying qualifying player rounds.

The current **Generate Content** button is not working.

This is the point where we are pivoting the content engine from generic AI-generated content into a **Creator Story Engine**.

IMPORTANT PRODUCT MODEL:

* The creator is NOT necessarily the player who played the round.
* The creator is reviewing a player's round and looking for interesting stories/content opportunities.
* Generated stories must therefore NEVER incorrectly write from the creator's/player's first-person perspective.
* The engine should identify the story opportunity and provide the creator with the evidence/material needed to create content about the player and their round.

This is a **web Creator Dashboard/content-engine change**.

Do NOT modify the mobile Post Round scorecard or Round Buddy UX.

Do NOT disrupt the existing working pipeline that gets qualifying rounds onto the creator dashboard.

The web Creator Dashboard is a **separate project/codebase** from the Post Round mobile application.

The web project does **NOT** have access to the mobile application's Round Buddy scorecard React Native component.

Therefore:

### DO NOT:

Use that actual database data to **assemble a compact web scorecard specifically for the Creator Dashboard**.

# Story Archetypes

Start with exactly these six archetypes:

### 1. Achievement

Something notable happened.

Examples:

* All fairways found
* Multiple birdies
* Eagle
* Personal best
* Exceptional putting
* Unusual scoring accomplishment
* Strong performance in a specific area

### 2. Drama

The round changed direction.

Examples:

* Strong comeback
* Difficult stretch followed by recovery
* Birdie streak
* Blow-up hole followed by recovery
* Front nine vs. back nine contrast
* Late-round turnaround

### 3. Surprise

Something about the round was unexpected.

Examples:

* Great score despite poor driving
* Excellent score despite missed greens
* Strong putting offset by poor approach
* Very low score after a poor start
* Unexpectedly strong/weak statistical category

### 4. Failure / Disaster

Something went badly and could make compelling or relatable content.

Examples:

* Blow-up hole
* Triple/quadruple
* Penalty sequence
* Multiple consecutive bogeys
* Major scoring collapse
* Particularly memorable bad hole

Do not make this insulting or overly negative. The goal is an interesting creator story, not criticism of the player.

### 5. Insight

Something meaningful can be learned from the round.

Examples:

* A specific part of the game strongly influenced the score
* Course management issue
* Putting was/wasn't the real problem
* Driving accuracy mattered more than distance
* A particular hole exposed a recurring weakness

### 6. Progress

Evidence that the player is improving.

This may require historical player-round data if available.

Examples:

* Better score than recent rounds
* Improved fairway percentage
* Improved putting
* More birdies
* Better back-nine performance
* New personal best
* Positive trend across recent rounds

If historical data is not available, do not fabricate progress. Simply omit the archetype if there is insufficient evidence.

# Story Evidence Package

Each generated Story Candidate should contain an evidence package.

The engine should combine information from THREE primary sources:

## 1. Scorecard

Use the actual player's round/hole data as the objective/statistical foundation.

Look for:

* Total score
* Score relative to par
* Hole-by-hole scoring
* Birdies
* Eagles
* Pars
* Bogeys
* Doubles/triples/other blow-ups
* Fairways
* Greens
* Putts
* Penalties
* Chips
* Sand shots
* Playable/miss annotations
* Front/back-nine differences
* Streaks
* Notable individual holes
* Other available round statistics

Only use fields that actually exist in the database.

Never invent missing statistics.

The web scorecard displayed to the creator must be assembled directly from these same underlying values.

## 2. Round Buddy highlights

If Round Buddy transcript/audio-derived transcript records are available for this round, analyze them for **notable moments**.

Look for:

* Memorable shot descriptions
* Excitement
* Frustration
* Funny moments
* Surprising outcomes
* Player reactions
* Memorable holes
* Self-deprecating comments
* Confidence
* Emotional turning points
* Interesting comments about what happened on a hole

Do NOT include every transcript.

Identify only the most relevant/high-value transcript highlights.

A transcript highlight should be tied to a specific hole or event whenever possible.

The purpose is to add the **human story behind the scorecard**.

Do not fabricate transcript content or quotes.

Only use actual stored transcript text.

IMPORTANT:

The web project may not have access to the mobile Round Buddy scorecard UI, but that does NOT prevent the Story Engine from using any Round Buddy transcript/data that is already available to the backend/database.

If Round Buddy transcript data is not available to the web project, continue using the scorecard rather than failing.

## 3. Performance/round analysis

Use existing round analysis/coaching data if it is already available.

Use it to identify meaningful insights.

Do not rebuild the coaching system.

# Ranking

The engine should prefer **fewer strong stories over many weak stories**.
