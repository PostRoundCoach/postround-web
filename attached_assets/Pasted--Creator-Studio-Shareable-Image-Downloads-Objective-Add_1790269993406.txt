# Creator Studio — Shareable Image Downloads

## Objective

Add on-demand downloadable shareable images to Creator Studio for:

1. **Round Highlights**
2. **Scorecard**
3. **Round Buddy Quips**

These are intended primarily as **visual overlays/assets for creator videos**, not as standalone AI-generated artwork.

Do **not** generate any images when a Creator Story is first revealed or when the page loads.

Each asset should be generated **only when the creator clicks its download action**, then automatically downloaded.

Use deterministic rendering from existing structured data.

**Do not introduce AI image generation.**

---

# 1. Important Architecture Rule

Before implementing anything, inspect the existing Creator Studio data-loading path and reuse the data that is already being loaded.

The existing Creator Studio round/story contract should remain the source of truth wherever possible.

**Do not create a separate collection of Supabase queries for each download button unless the existing contract genuinely does not expose a required field.**

The intended architecture is:

**Existing Creator Studio data → deterministic renderer → PNG → browser download**

not:

**Download button → new independent Supabase data model/query → image**

The renderer should receive a well-defined data object assembled from the existing Creator Studio contract.

---

# 2. Known Supabase Data Sources

The following schemas/data have been inspected and should be treated as the known underlying sources.

## `story_candidates`

This is the qualification/story-candidate source.

Relevant fields:

* `id`
* `round_id`
* `user_id`
* `story_type`
* `significance_score`
* `headline`
* `summary`
* `story_data`
* `status`
* `created_at`
* `updated_at`

Example:

```text
story_type: perfect_fairways
headline: Hit every fairway — 6 of 6
summary: An exceptionally accurate round off the tee: every fairway found, keeping the round in play throughout.
story_data.supporting_data.fairways_hit: 6
story_data.supporting_data.total_fairways: 6
```

Do not use `story_candidates` to re-qualify the story.

It is the existing qualification/input data.

Use its existing headline/summary/story data where appropriate for the Round Highlights asset.

# 3. Round Highlights Image

Create a branded horizontal image designed to sit naturally over creator video.

## Canvas

Use:

**1080 × 480 px**

This is intentionally a compact horizontal/video-overlay format.

It is **not** a full-screen vertical social image.

The design should have enough visual hierarchy to be readable when placed over creator video while remaining compact.

## Content

Build the image from existing authoritative round/story data.

Potential content includes:

* Player `display_name`
* Course name
* Round score
* Score relative to par
* Creator Story headline/title
* Story highlights
* Relevant round statistics
* Other structured information already exposed by the Creator Studio contract

Only display information that actually exists in the data.

**Never invent, infer, or hallucinate statistics.**

### Important

Prefer authoritative structured round aggregates already established by the application.

Do not scrape numbers out of the generated Creator Story `script`.

Do not recalculate authoritative round statistics from holes unless the existing application architecture specifically requires it.

For example, if structured data says:

```json
{
  "score": 36,
  "birdies": 3,
  "bogeys": 5,
  "three_putts": 5,
  "fairways_hit": 6,
  "total_fairways": 6,
  "GIR": 9
}
```

the renderer can safely use those values.

It should not independently count holes to arrive at a potentially different result.

## Branding

Every Round Highlights image should include:

**Post Round**
**Play. Learn. Share.**

Branding is part of the deterministic template.

## Output

Render as a PNG.

Use an overlay-friendly rendering approach with transparency where appropriate.

Do not create an opaque full-background image unless required by the established visual design.

## Generation behavior

When the creator clicks:

**Download Round Highlights**

the application should:

1. Gather the already-loaded Creator Studio data.
2. Render the 1080×480 asset deterministically.
3. Encode it as a PNG.
4. Automatically download it.
5. Make no AI/model call.

Show button-specific loading/progress while rendering.

Prevent duplicate concurrent generation from rapid repeated clicks.

Keep the existing larger Scorecard image format and existing Scorecard image-generation behavior.

**Do not redesign or unnecessarily rewrite the existing Scorecard renderer.**

* Branding

The Scorecard should continue to be generated **only when the creator clicks Download Scorecard**.

## Critical change: remove Round Buddy from Scorecard

The Scorecard image must contain **no Round Buddy content**.

Specifically:

* No Round Buddy quips
* No Round Buddy section
* No Round Buddy labels
* No Round Buddy commentary
* No Round Buddy messages
* No Round Buddy-derived copy

Remove any existing Round Buddy reference from the Scorecard image-generation/rendering path.

The Scorecard should represent the scorecard and relevant scorecard/round information only.

Do not add Round Buddy content as part of this task.

### Important architectural separation

The three asset types are intentionally separate:

**Round Highlights**
→ Creator Story + authoritative round data

**Scorecard**
→ Existing Scorecard renderer/data path

**Round Buddy**
→ Stored Round Buddy assistant messages

Do not merge these data sources simply because they all appear in Creator Studio.

## Generation behavior

When the creator clicks:

**Download Scorecard**

the application should:

1. Use the existing Scorecard renderer.
2. Generate the image on demand.
3. Encode/download it using the existing mechanism.
4. Preserve existing Scorecard behavior and appearance except for removing Round Buddy references.

Do not generate it when the story loads.

# 5. Round Buddy Quip Images

Round Buddy quips should be available as **individual downloadable horizontal overlays**.

## Canvas

Use:

**1080 × 480 px**

Use the same general visual language and dimensions as Round Highlights.

## Content

Each qualifying Round Buddy assistant quip gets its own downloadable image.

Conceptually:

**ROUND BUDDY**

> “That was ambitious.”

**HOLE 14**

The actual text must come directly from stored `round_buddy_messages.content`.

### Do not modify the quip

Do not:

* Rewrite
* Paraphrase
* Improve
* Summarize
* Regenerate
* Ask an AI model to recreate

the stored quip.

Render the actual stored content.

If `hole_number` exists, it may be displayed.

If it does not exist, do not invent one.

## Selecting qualifying quips

Use the application's existing Round Buddy qualification logic if one already exists.

Do not invent a new scoring/qualification algorithm as part of this task.

The likely source is:

`round_buddy_messages`

filtered to the appropriate:

* `round_id`
* user/story context
* `speaker_type = assistant`

but inspect the existing application logic before implementing the final filter.

## Branding

Each Round Buddy image should include:

**Post Round**
**Play. Learn. Share.**

Branding is deterministic.

## Output

Render as:

**1080 × 480 transparent/overlay-friendly PNG**

## Generation behavior

Each quip should have its own:

**Download**

action.

When clicked:

1. Render only that quip.
2. Use the 1080×480 PNG format.
3. Automatically download it.
4. Make no AI/model call.
5. Prevent duplicate rapid clicks.

Do **not** add a "Download All" action at this stage.

## Empty state

If there are no qualifying Round Buddy quips:

* Do not display an empty Round Buddy download section.
* Do not generate placeholder quips.
* Do not generate an image.

# 6. Overlay-Friendly Rendering

These assets are intended to be placed over creator video.

For:

* Round Highlights
* Round Buddy Quips

use an overlay-friendly PNG with transparency where appropriate.

The visual design should avoid unnecessarily large opaque backgrounds.

The graphic should feel like a polished Post Round layer that a creator can place over video.

For Scorecard:

* Preserve the existing Scorecard output format.
* Do not rewrite the renderer simply to make it consistent with the new overlay assets.
* If the existing renderer already supports transparent PNG output cleanly, it may be reused.
* Otherwise, leave its existing format intact.

Do not introduce a second image-generation infrastructure solely to support transparency.

Reuse existing infrastructure for:

* Canvas creation
* Font loading

* Browser download behavior
* Rendering utilities

Create separate renderers/templates for:

* `RoundHighlights`

The intended architecture is:

**Creator Studio contract/data → renderer → PNG → download**

not:

**Creator Story reveal → image generation**

and not:

**each download button → independent Supabase query**

unless the existing contract genuinely lacks the required data.

# Definition of Done

A creator can open a Creator Story immediately without waiting for image generation.

From Creator Studio they can independently:

* Download a **1080×480 Round Highlights overlay**
* Download the existing larger **Scorecard image**
* Download each qualifying **Round Buddy quip as an individual 1080×480 overlay**

Each asset:

* Is generated only when requested.
* Is automatically downloaded as a PNG.
* Uses real application data.
* Uses the existing Creator Studio data architecture.
* Uses consistent Post Round branding.
* Does not require AI image generation.

The Scorecard contains **no Round Buddy references**.

Round Highlights and Round Buddy use compact horizontal, overlay-friendly dimensions suitable for placement over creator video.
